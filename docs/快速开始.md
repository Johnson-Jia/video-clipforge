# 快速开始

## 前置依赖

### 必需

| 依赖 | 版本 | 用途 | 安装 |
|------|------|------|------|
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code) | latest | AI Agent 运行时 | `npm install -g @anthropic-ai/claude-code` |
| [Node.js](https://nodejs.org/) | >= 22 | HyperFrames CLI | `winget install OpenJS.NodeJS.LTS` 或 `brew install node@22` |
| [FFmpeg](https://ffmpeg.org/) | 任意 | 音视频处理 | `winget install Gyan.FFmpeg` 或 `brew install ffmpeg` |
| [edge-tts](https://github.com/rany2/edge-tts) | 任意 | 中文 TTS 旁白 | `pip install edge-tts` |
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | 任意 | YouTube 免版税音乐 | `pip install yt-dlp` |

### 自动安装（由 ClipForge 完成）

| 依赖 | 用途 |
|------|------|
| [HyperFrames](https://github.com/heygen-com/hyperframes) | HTML 转视频渲染，支持原生音频混音 |

### 可选

| 依赖 | 用途 | 安装 |
|------|------|------|
| GitHub CLI (`gh`) | GitHub 项目实时数据 | `winget install GitHub.cli` |
| jq | 精确音量标准化 | `winget install jqlang.jq` |

## 环境搭建

```bash
# 1. 克隆仓库
git clone https://github.com/Johnson-Jia/video-clipforge.git
cd video-clipforge

# 2. 一键安装（二选一）
bash install.sh                 # 项目级：装到当前项目 .claude/commands/（默认）
bash install.sh --global        # 用户级：装到 ~/.claude/commands/（跨项目共享）

# 3. 启动 Claude Code
claude
```

技能从 `.claude/commands/`（项目级）或 `~/.claude/commands/`（用户级）自动加载。

> **工作目录**：视频输出/evolution 数据落当前 git 项目根（`engine/lib/data_paths.py` 四级回退自动定位，cd 到不同项目即切换）。用户级 install 且在非 git 目录跑时，首次用 `/clipforge-switch-workspace <项目路径>` 设默认。

## 制作你的第一个视频

### 交互模式

在 Claude Code 中输入：

```
/clipforge Make a short video about the Rust programming language
```

Claude 会引导你完成每个阶段并请求确认：
1. **env-check** — 验证依赖已安装
2. **content** — 收集 Rust 相关信息
3. **design** — 确定视觉风格（编程主题采用暗色科技风）
4. **narration** — 编写分场景旁白脚本
5. **audio** — 生成 TTS 旁白 + 选择 BGM
6. **video** — 将 HTML 渲染为 MP4
7. **delivery** — 生成封面 + 抖音文案
8. **cleanup** — 清理中间文件

最终视频保存在 `workspace/YYYY/MM/DD/your-project/final.mp4`。

### 从 URL 生成

```
/clipforge Make a video from this article: https://example.com/article
```

### 从文件生成

```
/clipforge Make a video from this PDF: /path/to/document.pdf
```

## 定时任务自动化

ClipForge 内置三个定时任务命令，用于自动化内容生产：

### 每日 GitHub 趋势

```
/github-daily-trending
```

抓取当日 GitHub 热门项目，生成 25-45 秒视频。全自动运行，三源数据校验。

### 每周 GitHub 汇总

```
/github-weekly-trending
```

汇总本周 GitHub 顶级项目，按分类（AI/ML、前端、DevOps 等）分组。生成 45-60 秒视频。

### 每周知乎文章

```
/github-weekly-zhihu
```

生成本周 GitHub 亮点的知乎文章（纯文本内容，非视频）。

### 每日自进化（反同质化引擎）

```
/evolve-daily
```

运行自进化闭环：分析最新播放数据、提炼 pattern/Delta、训练播放量预测模型（启发式→回归，≥100 样本自动升级）。**这是让系统从真实反馈中进化的引擎**——发现"合规但没人看"的视频并校准评分。需配合定期导出播放数据（见下）。

### 播放数据回流（自进化燃料）

自进化依赖真实播放数据校准，平台不开放 API，需手动导出。建议每 2-3 天导一次（匹配平台数据 24-72h 稳定窗口）：

| 平台 | 文件 | 来源 |
|------|------|------|
| 抖音 | `抖音作品列表.xlsx` | 抖音创作者中心 |
| B站 | `b站近期稿件对比*.csv` | B站创作中心 |
| 视频号 | `微信视频号动态数据明细.csv` | 视频号助手 |
| 小红书 | `小红书笔记列表明细表.xlsx` | 小红书创作者中心 |

放到 `workspace/sources/视频数据/YYYY-MM-DD/`（一个日期一个目录）。导出后无需手动操作——当日 23:37 `/evolve-daily` 自动分析。这是用起自进化闭环的**唯一人工动作**。

### 配置定时任务

在 Claude Code 中调度每日任务：

```
/clipforge Schedule github-daily-trending to run daily at <your-preferred-time>
```

定时任务文件包含自续期逻辑 — 会在过期前自动延长调度。

## 视频模式

ClipForge 根据内容自动选择模式：

| 模式 | 触发条件 | 时长 | 场景数 |
|------|---------|------|--------|
| 标准 | 多主题 / 快速盘点 | 45-55 秒 | 6-8 |
| 深度解读 | 单主题详细分析 | 45-60 秒 | 7-8 |
| 电影解读 | 场景包含 `video_clip` 类型 | 3-5 分钟 | 不限 |

你可以在 prompt 中覆盖：`make a deep-dive video about X`。

## 内容分类

ClipForge 通过可插拔的分类配置文件支持多种内容类型。每个分类定义内容特定的规则（数据源、视觉风格、TTS 音色、标签），覆盖通用阶段的默认值。

| 分类 | 描述 | 定时任务命令 |
|------|------|-------------|
| GitHub | 开源项目趋势与分析 | `/github-daily-trending`、`/github-weekly-trending` |
| 频道置顶 | 个人介绍 / 频道定位视频 | `/clipforge` + 指定 intro 分类 |
| 漫画 | （即将推出） | — |
| 小说 | （即将推出） | — |

分类配置存放在 `.claude/commands/clipforge/categories/` 中。分类激活时，各阶段读取配置加载覆盖规则（例如 GitHub 分类设置 YunjianNeural 音色、暗色科技风格和 `#GitHub热门` 标签）。未指定分类时，所有阶段使用内置默认值。

添加新分类请参考 `CONTRIBUTING.md` → "添加新分类"。

## 输出结构

视频按日期组织在 `workspace/` 下：

```
workspace/
└── 2026/
    └── 05/
        └── 22/
            └── my-project/
                ├── final.mp4           # 最终视频（含 BGM）
                ├── final_no_bgm.mp4    # 最终视频（仅旁白）
                ├── cover.png           # 封面图
                ├── douyin.md           # 3 组抖音文案
                ├── design.md           # 视觉风格规范
                ├── narration.txt       # 完整旁白文本
                └── narration_segments.json  # 场景定义
```

清理后，每个项目占用不超过 30MB。

## 恢复中断的运行

ClipForge 使用基于文件的状态检测 — artifact 完成即其输出文件存在于磁盘上。如果运行被中断（超时、错误或手动停止）：

1. 使用相同项目目录重新运行 `/clipforge`
2. 已完成的阶段通过文件存在性自动检测并跳过
3. 从第一个未完成的阶段继续执行

要强制重新运行特定阶段，先删除其输出文件。例如重新渲染视频：

```bash
rm workspace/2026/05/22/my-project/output.mp4 workspace/2026/05/22/my-project/output_no_bgm.mp4
```

然后重新运行 `/clipforge`。

按阶段的错误恢复指南，请参见 [架构设计](架构设计.md) → "错误恢复"章节。

## 常见问题

### "HyperFrames not found"

在项目目录中运行 `npx skills add heygen-com/hyperframes`。

### "edge-tts failed"

确保已安装 edge-tts：`pip install edge-tts`。用 `edge-tts --text "hello" --write-media test.mp3` 测试。

### "视频没有声音"

检查项目目录中是否存在 `narration.mp3` 和 `bgm.wav`。如果缺失，重新运行 audio 阶段。

### "渲染超时"

较长视频（60 秒以上）可能需要增加超时。Stage 文件会自动处理标准时长内的超时问题。

### "BGM 太大声/太小声"

BGM 音量根据旁白响度自动分析。如果结果不理想，可以手动调整 `segment_durations.json` 中的 `meta.bgm_volume` 并重新运行 video 阶段。

### "Stage 运行中途失败"

重新运行 `/clipforge` — 已完成的阶段会自动跳过。如果错误仍然存在，检查对应阶段的输出文件并将其删除以强制重新执行。

### "yt-dlp 下载失败"

yt-dlp 用于 BGM 下载。如果失败，audio 阶段会回退到 Pixabay 搜索。确保 yt-dlp 已更新：`pip install -U yt-dlp`。

### "路径中的中文字符导致问题"

项目路径请仅使用英文。`workspace/` 目录使用 `YYYY/MM/DD/project-name/` 格式，不含中文字符。
